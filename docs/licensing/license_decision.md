# 许可选择与公开源码前的安排

当前原创源码采用 **ShenScope Contribution-Only License 1.0**。
正式条款见根 [LICENSE](../../LICENSE)，贡献授权见 [CONTRIBUTING.md](../../CONTRIBUTING.md)。
仓库仍为私有，计划以后公开源码；本次许可切换没有改变 GitHub 可见性。

## 为什么选受限贡献许可

本项目希望其他人能提交改进，同时保留对独立发行、衍生产品和商业使用的控制。
普通开源许可无法同时满足这些限制；AGPL 也允许商用和独立衍生，不要求向原仓库提 PR。

因此，原创部分使用仅贡献许可，明确允许为 PR 准备、测试和提交所必需的
复制、修改和运行。其他项目里的普通使用、商业部署和独立发行需要另行书面授权。
README 使用受限许可的准确说明，不把它宣称为标准开源。

查看、fork 和托管权限按平台条款保留；第三方材料与既有合法授权的权利不受追溯限制。
本许可保护具体作品的使用边界，不授予对抽象想法或独立开发的垄断权。

## 为什么还要处理旧历史

此前私有开发提交使用 Apache-2.0。仅修改最新提交的 LICENSE，并不能安全地
将那些历史版本公开后再要求别人不得使用其中的 Apache 代码。
是否曾授出有效权利要核对实际接收者；任何已合法授出的权利都需要保留。

本仓库保留私有开发历史，帮助追踪功能和作者。当前历史不适合直接完整公开为
“全部源码仅允许贡献”的发行仓库。向新的外部贡献者开放完整历史前，也需要
处理这些旧许可，不能仅靠私有可见性规避已有文本的授权问题。检查命令：

```bash
python scripts/audit_publication_license.py
```

该命令只读取本地分支、标签及可达提交中的根 LICENSE，不修改文件或 Git。
发现旧许可时返回退出码 1，表示受限许可的完整历史公开检查未通过。
它不验证法律有效性、GitHub 可见性、服务端缓存、不可达对象或第三方发行义务。

## 正式公开时

1. 核对原创部分的授权权利、任何已有接收者及贡献授权。
2. 保留私有开发仓库，将经过检查的当前源码、受限许可和必要的第三方声明组成公开发行快照。若选择公开开发历史，必须逐项清理许可冲突，并核对服务端残留；不能只修改 HEAD 或只依赖一次本地历史重写。
3. 不向公开发行仓库导入仍带旧 Apache 源码的提交、分支、标签或恢复文件。私有验证记录继续在私有仓库保存。
4. 验证公开快照、VSIX 及未来 IDE 包的许可证、NOTICE、组件声明与贡献入口一致。
5. 法律审阅后，再单独执行公开或发布操作。本次未创建新 GitHub 仓库，也未更改现有仓库可见性。

GitHub 公开仓库允许的服务内查看和 fork 无法由项目许可取消。
参考 [GitHub D.5/D.6](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service)。
