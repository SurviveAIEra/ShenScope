This inventory covers every named research checkout together. It prevents a
module-only comparison from overlooking workflow, UX, interoperability and
operational strengths. Each row is a research direction, not a claim that every
upstream behavior has been audited or implemented. Immutable revisions and
actually inspected source paths are in `reference_lockfile.json`. README claims
require further source/test verification before they become acceptance evidence.
No upstream agent implementation is copied, embedded or translated into Julia.

## Combined acceptance domains

Evaluate all applicable projects in each domain, recording source, revision,
design consequence, verification case and remaining gap. Projects with a
different scope remain in the inventory instead of receiving invented features.

1. Agent loop, streaming/provider capabilities, routing and recovery.
2. Goals/context/compaction/retrieval, reasoning replay and memory.
3. Editing/search/processes/Git/tests, scheduling and side-effect ownership.
4. Permissions, isolation, budgets, credentials, trust and audit.
5. Durable sessions, tasks/leases/mailboxes and background execution.
6. MCP/resources/prompts, skills/hooks and extension contracts.
7. Syntax/semantic/project graph facts, incremental updates and analyzers.
8. CLI/TUI/VSIX/native Workbench UX, accessibility, distribution and observability.

Present verified behavior and missing capabilities separately. The initial
streaming/tool/agent checkpoint and shared editor protocol do not establish
complete synthesis, superiority, live-model quality or the Core size target.
